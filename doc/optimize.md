经过测试，在处理大文件，比如 `babel.js` 时，该文件大小是 `2.98MB`，基于 `native messaging` 的处理时间甚至不到 `1s`！（指的是处理 JS 文件，不包括插件重写响应等耗时）。

# 将 base64 编码与解码优化

浏览器重写响应时：

1.  拿到的是 `base64` 编码的数据
2.  在当前实现中（未优化之前），插件中进行解码便于调试
3.  发给 `native messaging` 处理
4.  `native messaging` 处理完成之后编码，发回给插件，便于调试
5.  插件再编码（`base64 encode`）完成响应重写

所以浏览器中存在大量 `base64 encode` 和 `base64 decode` 操作，这显然是低效的。

所以采取下面的措施：

-   浏览器拿到原始响应后，直接发给 `native host`，由本地程序进行 `base64 decode` 再处理
-   `native host` 处理完成之后，直接编码成 `base64` 再发给插件，插件直接用它重写响应

# 避免重复以及调用链说明

当前主要记录字符串，其它的暂时忽略。重点在于**重复的值**该怎么办！简单说明如下：

```js
// 如下，在 hook 方法中将记录重复的值 'hello'，该怎么办？
const a = hook("hello");
const b = hook(a);
```

诚然，最简单的方式就是**只记录该值第一次出现的地方**，如果后续又出现了该值，直接忽略！

我使用**基于函数调用链的过滤方式**，具体以下说明：

假设一个值第一次出现的完整堆栈为：`A --> B --> C`，即该值出现在 `C` 函数中，那么：

-   当 `A、B` 函数中出现了该值时，认为它是 `C` 作用域中返回的，忽略记录
-   当该值再次出现的完整堆栈为 `A --> B --> C --> D --> E`，即该值出现在 `E` 函数中时，认为它是从 `C` 函数传参调用来的 —— 无论 `D` 函数中是否出现该值
