此前注入 Hook 脚本的方式是利用插件的 `content scripts` 机制，可以注入到多种脚本作用域中 —— 除了 `Worker` 作用域！而且也**无法保证注入的代码一定在网站代码之前运行**。

>   根据插件的开发文档，插件的 `scripting、userScripts` 等注入脚本的 API 都可以在网站加载之前将脚本注入到网页中，但无法保证，脚本注入到网页的时候，网页是否已经加载，也就是说：**它能保证及时注入，但不能保证及时运行，注入的过程也就是要时间的！**尤其是遇到内联 `<script>` 时偶尔失效。

现在需要调整注入逻辑，也是为了处理 html 文档中 `<script>` 的 js 代码。

第一步，将核心 HOOK 代码以 `iife` 格式编译到本地 js 文件。

第二步，当在插件开启功能时，增加对 `html` 文档的处理，主要有：

1.   插件拦截 html 并将其内容发送给本地程序 `native host`
2.   本地程序提取 html 中 `<script>` 的 js 并进行处理
3.   将 hook 代码插入到 html 文档顶部
4.   将处理过的 html 返回给浏览器插件，完成响应重写

额，整个方案看下来，浏览器插件主要负责响应重写，核心逻辑都在本地处理。

嗯？好像和原项目使用中间代理服务器差不多，不过是借由插件来操作了。



# 配置项的传递

当前关于 Hook 的配置项主要是过滤一些多余的值，比如字符串的最小长度、最大长度等等，也可以自定义过滤函数。

**但是真的需要浏览器插件提供 UI 来配置，然后传递给本地程序**？现在注入的 hook 代码都已经分离到本地了，直接修改本地的 js 文件岂不是更方便？也可以用到其它地方，还是不要和插件绑定太深！
